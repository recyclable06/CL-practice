# 持续学习代码训练

主线：**顺序微调 → Experience Replay（ER）→ DER++**。

目标是在约 40 小时的练习中，从“看过并能默写训练脚本”，进步到能够独立拆解、实现、调试和验证一个小型论文工程。预计每周 5 小时、约 8 周，按实际能力允许延长至 9—10 周。

这是独立实现训练项目。实验采用缩小规模，不以复现原论文完整指标或产生科研创新作为完成条件。

## 项目应交付什么

- 学习者亲自编写的小型训练项目，支持统一协议下的顺序微调、ER 和 DER++。
- 足够让他人在相同条件下启动实验的环境、命令和配置说明。
- 一组可追溯的对照结果，以及少量围绕明确问题的实验。
- 实现与参考代码的关键差异说明；不要求逐行比较。
- 至少一次独立排错或未提前看答案的功能改动记录。

代码目录、文件拆分和函数接口由学习者逐步设计，目前不预先生成完整骨架。若需要缩减范围，按训练计划记录原因及未完成部分。

## Git 中保留什么

保留源代码、文档、实际使用的环境说明、轻量配置、汇总指标及值得讨论的小图。每个有意义的改动可形成一个提交，提交说明写清改变了什么。

原始数据、模型权重、缓存文件和大量运行日志放在被忽略的目录中；有展示价值的结果另行整理为小文件提交。`.gitignore` 只提供默认过滤，提交前仍需查看实际差异，尤其是集群账户和密钥信息。

本目录已初始化为本地 Git 仓库，并有初始提交。远程同步状态尚未核实；确认远程地址后再配置同步。

## 第一阶段运行说明

入口：[阶段1.py](阶段1.py)。2026-10-17 核实的本地环境：Windows 11、Python 3.13.7、torch 2.14.1、torchvision 0.29.1。以上是当前环境记录，不代表其他版本不兼容。

在本项目目录下，使用已安装依赖的环境运行。当前 Windows 虚拟环境命令为：

```powershell
.\.venv\Scripts\python.exe .\阶段1.py
```

数据保存到当前工作目录的 `data/`；脚本使用 torchvision 的 CIFAR-10 接口和代码中指定的下载镜像。已有数据可复用。设备由脚本根据 CUDA 是否可用选择。

当前配置写在脚本顶部：5 个 epoch、batch size 8、Adam 学习率 0.001。原训练集按固定划分种子 1 随机分成 45000 条训练、5000 条验证数据；训练批次打乱。模型初始化尚未固定随机种子，不保证重复运行得到相同指标。

控制台输出训练 loss、验证 loss、验证正确数/总数，以及保存加载前后的固定样本 logits 和最大差异。checkpoint 写入当前目录的 `ckpt_ep{epoch}.pt`，轮次从 0 开始；再次运行会覆盖同名文件。权重受 `.gitignore` 过滤，不纳入代码提交。

学习者实际完整运行的指标与完成情况记录在[进展记录](进展记录.md)。AI 小规模审查的指标仅用于验证代码行为，不能代替完整实验结果。

## 第一阶段重构对照（AI 示范）

[阶段1重构.py](阶段1重构.py) 是用户授权 AI 编写的学习对照版，原版保留，不计为学习者独立实现。此版本创建时第二阶段尚未开始；当前进度见上文。

值得做的是单文件内的职责拆分：先读 `main()`，看到准备数据和对象 → 训练一轮 → 验证 → 保存 → 加载核对；再进入相应函数看实现。没有引入 Trainer 类、配置框架或多文件目录。

| 原写法或问题 | 对照版的写法 | 为什么这样写／适用边界 |
| --- | --- | --- |
| 全部逻辑在文件顶层 | `main()` 调用数据构建、训练、验证、加载检查函数；加入口保护 | 主流程可以直接阅读；导入文件不会立即下载或训练。函数按完整职责拆，不是每几行拆一次 |
| `v2.ToTensor()` | `v2.ToImage()` → `v2.ToDtype(torch.float32, scale=True)` | 原 API 已弃用。前者转换图像表示，后者转换 dtype 并缩放 uint8 范围到 [0,1]；不等于均值方差标准化。对本项目 RGB 图像含义一致，可能有微小浮点舍入差异 |
| 验证循环外 `with torch.no_grad()` | 验证函数上 `@torch.no_grad()` | 整个函数无需梯度时更清晰；原写法也正确。它不能代替 `model.eval()`，两者控制不同事情 |
| 各 batch 的平均 loss 再平均 | `loss.item() * batch样本数` 累计，除以实际样本数 | 最后一个 batch 不足时仍正确。原版 45000/5000 都能被 batch=8 整除，原结果不因此失效；此写法假定当前无类别权重的交叉熵采用默认 mean |
| `optimizer.zero_grad()` | 显式 `set_to_none=True` | 当前版本本来就默认 True，这不是修 bug。明确清除梯度的方式；不是手动把每个梯度填成 0，两者在参数未参与计算时可能有行为差异 |
| 同一个 generator 用于划分和 shuffle；模型初始化未固定 | 两个独立 generator，加 `torch.manual_seed` | 分开随机状态，减少流程耦合，同时固定模型初始化。不保证跨硬件、跨版本逐位一致 |
| 相对当前工作目录的路径 | `Path(__file__).resolve().parent` 定位项目目录 | 从不同目录启动时仍能找到同一份数据；新权重写到独立子目录 |
| 加载后打印差异，人工判断 | 显式 `weights_only=True`，再用 `torch.testing.assert_close` 检查 | 明确使用适合 tensor/state_dict 的加载方式；超过容差直接报错。`weights_only` 不是只取模型权重字段，仍可加载本例的 optimizer 字典 |

`train_one_epoch` 不需要返回模型：传入的是同一个模型对象，`optimizer.step()` 会原地更新参数和优化器状态。它返回用于汇报的 loss。`evaluate` 不更新参数，但会切换模型模式；下一轮训练由 `train_one_epoch` 显式切回 `train()`。

原版合适的做法继续保留：`nn.Sequential` 描述简单网络、原始 logits 交给 `CrossEntropyLoss`、训练与验证区分模式、用 `state_dict` 保存参数。没有额外加 softmax、标准化或新模型，因为这些属于实验方案变化，不是代码更清晰的必要条件。

运行对照版：

```powershell
.\.venv\Scripts\python.exe .\阶段1重构.py
```

仍为同一 CNN、5 轮、batch=8、Adam lr=0.001 和余弦调度。数据位于脚本所在目录的 `data/`，权重位于 `checkpoints/阶段1重构/`，重复运行会覆盖该子目录内同名文件。保留原 checkpoint 三个字段；没有补齐 scheduler 和随机状态等信息，不声称支持完整断点续训。

这不是逐位不变的整理：固定模型种子、分开 generator 会改变训练轨迹；新 transform 可能有舍入差异；加载检查改用一个验证 batch。不要要求重新训练的准确率等于原版 63.96%。检查范围和结果见进展记录。

建议对照时优先看两个问题：在 `main()` 能否看清实验顺序；在每个函数能否说清“输入什么、返回什么、改变了什么状态”。先理解这些，再考虑把哪种写法用于第二阶段，不需要把 AI 版本重新默写一遍。

API 依据：[ToTensor 弃用及替代方式](https://docs.pytorch.org/vision/stable/generated/torchvision.transforms.v2.ToTensor.html)、[zero_grad](https://docs.pytorch.org/docs/2.14/generated/torch.optim.Optimizer.zero_grad.html)、[torch.load](https://docs.pytorch.org/docs/2.14/generated/torch.load.html)。
